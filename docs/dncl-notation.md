# 共通テスト用プログラム表記（新DNCL）仕様まとめ

生徒向けWebアプリ実装のための言語仕様リファレンス。
一次情報（大学入試センター公式）＋実際の出題例＋講座資料をつき合わせて整理した。

最終更新: 2026-08-17

## 0. 前提：2つの表記が存在する

| | 名称 | 対象科目 | 代入 | 出典 |
|---|---|---|---|---|
| 新 | **共通テスト用プログラム表記** | **情報Ⅰ**（2025年〜） | `=` | 試作問題「情報」概要 p.18-20 |
| 旧 | 共通テスト手順記述標準言語（DNCL） | 情報関係基礎 | `←` | DNCLの説明（2022年1月） |

**このアプリで実装するのは「新」＝共通テスト用プログラム表記**。
「DNCL」は通称として新表記を指して使われることが多いが、公式には情報Ⅰでは DNCL という語は使われない。

公式の但し書き（両文書に共通）:
> 問題文の記述を簡潔にするなどの理由で、この説明文書の記述内容に従わない形式で出題することもあります。
> したがって受験に際しては、当該問題文の中の説明や指示に注意し、それらに沿って解答してください。

→ **仕様は「ゆるい」ことが公式に明言されている**。アプリは厳密なパーサより「揺れを許容する寛容なパーサ」にすべき。

## 1. 変数

- 変数名は**英字で始まる英数字と `_` の並び**。例: `kosu`, `kingaku`, `kingaku_kei`
- 命名の慣例（特に指示がない限り）:
  - **小文字始まり → 通常の変数** … `kosu`, `sousuu`, `maisu`, `nokori`
  - **大文字始まり → 配列** … `Tokuten`, `Tomei`, `Tokuhyo`, `Hikaku`, `Tosen`, `Kouka`
  - **全部大文字 → 実行中に変化しない値（定数）**
- 変数名はローマ字表記（`kizyunsuu`, `tosenkei` など）が使われる。
- 型宣言はない。数値と文字列を同じ変数に入れられる。

## 2. 値

- 数値は10進法。整数・小数の区別なし（`100`, `99.999`）
- 文字列は**ダブルクォーテーション** `"..."` で囲む。例: `"Komaba"`, `"I'll be back."`
  - 旧DNCLでは `「...」` も使えたが、新表記は `"..."`
  - 問題PDFでは全角の `”…”` に見えることがある（フォント差）。パーサは `"`, `“`, `”`, `「」` を全部許容するのが安全。
- **文字列連結は `+`**。例: `message = "祇園精舎の" + "鐘の声"`
- 真偽値は比較・論理演算の結果として現れる（リテラルは特に規定なし）

## 3. 配列

```
Data = [10, 20, 30, 40, 50, 60]
Tokuten[3]              1次元
Data[2, 4]              2次元（添字をカンマ区切り）
```

- **添字は公式例示では 0 から始まる**（p.19 の二分探索例は `Data[0]`〜`Data[9]`）
- ただし**問題によっては 1 から始まる**。旧DNCL説明にも「問題によっては1以上の添字のみを扱います」と明記。
  - 実例: **令和7年度本試験 第3問は 1 始まり**（`Akibi[0]` をダミーにして 1 から使う形）
  - 試作問題・サンプル問題は 0 始まり
  - → **アプリでは「添字の開始を 0/1 で切り替えられる」ことが必須**。問題文の指示が絶対。
- 一括代入の自然文表現がある:
  ```
  Tokuten のすべての値を 0 にする
  ```
  （旧DNCLの「Tokuten のすべての要素に 0 を代入する」と同義）

## 4. 代入文

```
kosu = 3
Tokuten[4] = 100
kingaku_goukei = kingaku * kosu
kosu = 3, kingaku = 300          複数の代入を「,」区切りで1行に（左から順に実行）
nyuryoku = 【外部からの入力】     外部入力
```

- `=` は「右辺を計算して左辺に入れる」。等号ではない。
- したがって `x = x + 1` は「x に 1 を加えて更新」。**これが最頻出のつまずきポイント**。
- 旧DNCLにあった `kosu を 1 増やす` / `saihu を syuppi 減らす` は新表記の公式例示には無い。

## 5. 演算子

### 算術
| 記号 | 意味 | 例 | 結果 |
|---|---|---|---|
| `+` | 加算・文字列連結 | `6 + 4` | `10` |
| `-` | 減算 | `6 - 4` | `2` |
| `*` | 乗算 | `6 * 4` | `24` |
| `/` | 除算（実数） | `6 / 4` | `1.5` |
| `÷` | **商の整数部分** | `46 ÷ 10` | `4` |
| `%` | 剰余 | `46 % 10` | `6` |
| `**` | べき乗 | `6 ** 4` | `1296` |

優先順位: `**` > `*` `/` `÷` `%` > `+` `-`。丸括弧 `( )` で明示可。同順位は左から。

### 比較
`==`（等しい） `!=`（等しくない） `>` `>=` `<` `<=`
文字列にも `==` / `!=` が使える。

### 論理
`and`（論理積） `or`（論理和） `not`（否定）

- 旧DNCLの `かつ` `または` `でない` に対応。
- **優先順位はなく左から評価される**（旧DNCL説明に明記）。丸括弧で順序指定。
  `a and b not` は `(a and b) not` と解釈される、というのが旧DNCLの規定。新表記では `not` は前置なので実質 `not` > `and`/`or` として扱ってよいが、問題では必ず括弧か単純な形で出る。

## 6. 表示（出力）

```
表示する("整いました")
表示する(kosu, "個見つかった")
表示する(Kamoku[i], "の得点は", Tensu[i], "です")
表示する(Tomei[m], ":", Tosen[m], "名")
```

- 引数は**カンマ区切り**。文字列と数値を混在させて連結表示する。
- 区切り文字は入らない（そのまま連結される）。
- 旧DNCLは `「...」と kosu と「個」を表示する` という語順だった。**新表記は関数形式**。

## 7. 関数

### 組み込み（公式例示に登場）
| 関数 | 戻り値 | 例 |
|---|---|---|
| `表示する(...)` | なし | 出力 |
| `要素数(配列)` | 配列の要素数 | `要素数([10,20,...,80])` → `8` |
| `乱数()` | 0以上1未満の小数 | `saikoro = 整数(乱数() * 6) + 1` |
| `整数(値)` | 整数化 | 同上 |

- **`表示する` 以外の関数は、基本的に問題文中で説明される**（公式注記）。
  実際の出題例: `切り捨て(x)`（サンプル問題）、`枚数(金額)`（試作問題）
- **関数名は日本語が使われる**。呼び出しは `関数名(引数, 引数)`。

### ユーザー定義関数
新表記の公式例示には定義構文の記載がない。実際の出題は「関数の仕様を日本語で説明し、その中身を作らせる／使わせる」形式（試作問題 第3問の `枚数(金額)`）。

参考として、旧DNCLの定義構文と、講座資料で使われている形式:
```
関数 和を表示する(n) を        ← 旧DNCL
│  ...
と定義する

関数定義 面積(teihen, takasa):   ← 講座資料で採用している便宜的な書き方
│  keisan = teihen * takasa / 2
└  戻り値(keisan)
```
アプリで関数定義を扱うなら **`関数定義 名前(引数):` … `戻り値(式)`** を採用する（講座資料と整合）。ただし「公式仕様ではない」と明示すること。

## 8. 制御文

インデントは **`│`（縦線）で制御範囲、`└` で範囲の終わり**を示す。
条件・繰り返しのヘッダ行は **`:`（コロン）で終わる**。

### 条件分岐
```
もし x < 3 ならば:
│  x = x + 1
│  y = y + 1
そうでなくもし x < 0 ならば:
│  x = x * 2
そうでなければ:
└  y = y * 2
```
- `そうでなくもし` は0個以上、`そうでなければ` は0個または1個。
- 旧DNCLは `もし〈条件〉ならば … を実行し、そうでなければ … を実行する` と閉じる形。

### 繰り返し（順次＝カウンタ制御）
```
x を 0 から 9 まで 1 ずつ増やしながら繰り返す:
│  goukei = goukei + x
└
```
- `減らしながら` もある。例: `i を 4 から 0 まで 1 ずつ減らしながら繰り返す:`
- **終了値は含む**（0から9なら10回）。
- 実行手順（旧DNCL説明の規定、新表記も同じ）:
  1. 変数に初期値を代入
  2. 変数の値が終了値より大きければ（減らす場合は小さければ）終了
  3. 処理を実行 → 変数に差分を加える → 2に戻る
- 配列の全走査は `0 から 要素数-1 まで`（0始まりの場合）。

### 繰り返し（条件制御・前判定）
```
n < 10 の間繰り返す:
│  goukei = goukei + n
└  n = n + 1
```
- 条件が成り立つ間くり返す。0回実行もありうる。
- 実例: `tosenkei < giseki の間繰り返す:`

### 繰り返し（後判定）
旧DNCLには `繰り返し, 〈処理〉 を, 〈条件〉になるまで実行する` がある。
新表記の公式例示には無い。**アプリでは実装しなくてよい**（出題実績なし）。

## 9. コメント

```
atai = 乱数()    #0以上1未満のランダムな小数を返す
aida = (hidari + migi) ÷ 2    #演算子÷は商の整数値を返す
```
- **`#` 以降は行末まで処理の対象外**。

```

## 11. 公式リファレンス実装例（二分探索）

概要「情報」p.19 に載っている**公式の完全なコード例**。パーサのテストケースとしてそのまま使える。

```
(1)  Data=[3,18,29,33,48,52,62,77,89,97]
(2)  kazu=要素数(Data)
(3)  表示する("0〜99の数字を入力してください")
(4)  atai=【外部からの入力】
(5)  hidari=0 , migi=kazu-1
(6)  owari=0
(7)  hidari <= migi and owari==0 の間繰り返す:
(8)  │  aida=(hidari+migi)÷2      #演算子÷は商の整数値を返す
(9)  │  もし Data[aida]==atai ならば:
(10) │  │  表示する(atai,"は",aida,"番目にあります")
(11) │  │  owari=1
(12) │  そうでなくもし Data[aida]<atai ならば:
(13) │  │  hidari=aida+1
(14) │  そうでなければ:
(15) │  └  migi=aida-1
(16) もし owari==0 ならば:
(17) │  表示する(atai,"は見つかりませんでした")
(18) 表示する("添字"," ","要素")
(19) i を 0 から kazu-1 まで 1 ずつ増やしながら繰り返す:
(20) └  表示する(i,"  ",Data[i])
```

0 3
1 18
...
```

## 12. 出題で頻出のアルゴリズム定型

アプリの練習問題・解説はこの型を軸に組むとよい。

### 累計（合計）
```
goukei = 0
i を 0 から 要素数(Data)-1 まで 1 ずつ増やしながら繰り返す:
└  goukei = goukei + Data[i]
```

### 最大値とその添字
```
max = 0                     ← 最小値探索なら十分大きい初期値（例 100, 1000）
i を 0 から 3 まで 1 ずつ増やしながら繰り返す:
│  もし max < Hikaku[i] ならば:
│  │  max = Hikaku[i]        ← 「新しい暫定1位の値」を入れるのが正解型
└  └  maxi = i               ← 添字も同時に保存

表示する(Namae[maxi])
```
誤答選択肢の定番: `max = max + 1` / `Hikaku[i] = max` / `Tokuhyo[i] = Hikaku[i]`

### 値の一時保存（swap・更新前の値の利用）
```
temp = suugaku
suugaku = suugaku + 10
goukei1 = temp + eigo       更新前の値を使う
goukei2 = suugaku + eigo    更新後の値を使う
```

### 貪欲法（硬貨の枚数）— 試作問題 第3問 問2
```
Kouka = [1,5,10,50,100]
kingaku = 46
maisu = 0, nokori = kingaku
i を 4 から 0 まで 1 ずつ減らしながら繰り返す:
│  maisu = maisu + nokori ÷ Kouka[i]
└  nokori = nokori % Kouka[i]
表示する(maisu)
```

### 全探索して最小を更新 — 試作問題 第3問 問3
```
kakaku = 46
min_maisu = 100
tsuri を 0 から 99 まで 1 ずつ増やしながら繰り返す:
│  shiharai = kakaku + tsuri
│  maisu = 枚数(shiharai) + 枚数(tsuri)
│  もし maisu < min_maisu ならば:
└  └  min_maisu = maisu
表示する(min_maisu)
```

### ドント方式の議席配分 — サンプル問題 第2問
```
Tomei = ["A党","B党","C党","D党"]
Tokuhyo = [1200,660,1440,180]
Tosen = [0,0,0,0]
tosenkei = 0
giseki = 6
m を 0 から 3 まで 1 ずつ増やしながら繰り返す:
└  Hikaku[m] = Tokuhyo[m]
tosenkei < giseki の間繰り返す:
│  max = 0
│  i を 0 から 3 まで 1 ずつ増やしながら繰り返す:
│  │  もし max < Hikaku[i] ならば:
│  │  │  max = Hikaku[i]
│  └  └  maxi = i
│  Tosen[maxi] = Tosen[maxi] + 1
│  tosenkei = tosenkei + 1
└  Hikaku[maxi] = 切り捨て(Tokuhyo[maxi] / (Tosen[maxi] + 1))
k を 0 から 3 まで 1 ずつ増やしながら繰り返す:
└  表示する(Tomei[k],":",Tosen[k],"名")
```

## 13. アプリ実装上の注意（設計メモ）

1. **添字の基点を問題ごとに 0/1 切り替え可能に**。デフォルトは0、問題文で指定があればそれに従う旨をUIに出す。
2. **`÷` と `/` の区別**を必ず実装。`/` は実数、`÷` は商の整数部分。負数の扱いは出題実績がないので、切り捨て（floor）ではなく0方向切り捨て（truncate）でも差は出ないが、floor で統一しておく。
3. **`%` は剰余**。`÷` と組で使われる。
4. **インデントは `│` `└` だが、半角スペースやタブでの字下げも受け付ける**。問題PDFからのコピペと手入力の両方を通したい。
5. **全角/半角の揺れを正規化**してからトークナイズする:
   - 全角英数字・全角スペース → 半角
   - `＝` → `=`、`（）` → `()`、`［］` → `[]`、`”“` → `"`
   - `：` → `:`、`，` → `,`
6. **行番号 `(1)` `(01)` が行頭にあっても無視**して解釈できるようにする（問題PDFからそのまま貼れる）。
7. **`もし〜ならば：` の全角コロンも許容**。コロンが無い行も許容してよい（問題文で省略されることがある）。
8. **実行トレース表示が学習効果の中心**。1行ずつのステップ実行と、各変数・配列の値の変化を表で出せること。共通テストの図8（配列の変化を追う表）がそのまま再現できる形が理想。
9. **エラーメッセージは日本語で、原因を生徒の言葉で**。「添字が範囲外です（Data は 0〜5 まで。7 が指定されました）」のように。
10. 未定義変数の参照は、出題では起きない。エラーにするか 0 扱いにするかはアプリの方針次第だが、**エラーにして指摘する方が学習になる**。

## 14. 講座資料（自作）と公式仕様の差分

`reference/course01_basics.pdf` の記述で、公式と照らして注意が必要な点:

| 箇所 | 講座資料 | 公式・実際 |
|---|---|---|
| 比較演算子表 | 「小なり」の行が `<=` | 正しくは `<`（資料の誤植） |
| 配列の添字 | 「必ず0から数える」 | 公式例示は0始まりだが**1始まりの出題もある**（令和7年度本試験） |
| 関数定義 | `関数定義 名前(引数):` / `戻り値(x)` | 新表記の公式仕様には定義構文の規定なし（資料の但し書きどおり便宜的なもの） |
| 条件分岐の閉じ | `│` のみ | 公式は最終行を `└` で閉じる |
