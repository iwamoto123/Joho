### ⚠ `?v=N` を必ず上げること

JS/CSSは **1年間ブラウザにキャッシュされる**設定（`Cache-Control: immutable`）にしてある。
`index.html` と `teacher.html` の中で

```html
<link rel="stylesheet" href="style.css?v=9">
<script src="app.js?v=9"></script>
```

のように参照しているので、**JSかCSSを変更したら `?v=` の数字を全部+1して上げないと、
生徒の端末に新しいコードが届かない**。HTML自体はキャッシュしない設定なので、
数字を上げれば必ず反映される。

```bash
perl -pi -e 's/\?v=9/?v=10/g' index.html teacher.html
```

Vercel の GitHub App が `iwamoto123/Joho` にアクセス権を持っていないため、
`vercel git connect` に失敗して連携できていない。**push しても本番は更新されない**。

## 6. 設計の要点

### 6.1 URLの形（ルーティングはハッシュ）

| URL | 内容 |
|---|---|
| `#/` | 問題セット一覧 |
| `#/s/<setId>` | セットの目次 |
| `#/p/<setId>/<probId>` | 組み込み問題 |
| `#/d/<Base64>` | 先生が作った単問（データはURLの中） |
| `#/ds/<Base64>` | 先生が作ったセット |

先生画面の「URLを発行する」が `#/d/` `#/ds/` を作る。問題を直したらURLも作り直して配り直す。

### 6.2 問題データの形（problems.js / 先生画面のJSONと共通）

```js
{
  id: 'q1',
  title: '(1) 合計点と平均点',
  question: '…HTML可…',
  hint: '…',
  indexBase: 0,               // 配列の添字の開始。0 または 1
  code: [                     // 1要素1行。{{n}} が穴埋め欄
    'Seiseki = [50, 30, 60, 45, 85]',
    'total = 0',
    'i を 0 から {{1}} まで 1 ずつ増やしながら繰り返す:',
    '└  {{2}}'
  ],
  blanks: [                   // 空欄ごとの正解と解説
    { id: 1, answer: '4', explain: '…' },
    { id: 2, answer: 'total = total + Seiseki[i]', explain: '…' }
  ],
  choices: ['4', '5', 'total = total + Seiseki[i]', 'total = Seiseki[i]'],  // 正解＋誤答
  dataTable: { head: [], rows: [[]] },  // 任意。問題ごとの表（セットの表より優先）
  concept: [                            // 任意。「解き方のイメージ」紙芝居スライド
    { t: 'スライドの見出し', d: '<div>…本文HTML…</div>' }
  ]
}
```

セットは `{ id, title, intro, dataTable, problems: [...] }`。
`dataTable` は問題文の下に出る表（`{head:[], rows:[[],[]]}`）。問題側に `dataTable` があればそちらが優先。

`concept` のスライド本文は problems.js 冒頭のヘルパー（`row/box/ar/big/note/flow/cells`）で組み立てる。
変数の箱・オレンジ矢印・手順フロー・配列セル図が数行で書ける。組み込みの全23問にスライドを付けてある。

**採点は空白を無視した文字列一致**（`DNCL.normalize` で全角→半角にしてから空白除去）。
そのため「同じ意味だが書き方が違う正解」は不正解になる。選択肢から選ばせる形式なので実害はない。

### 6.3 インタプリタ（dncl.js）

`DNCL.execute(codeLines, {indexBase, inputs, maxSteps})` → `{steps, output, error}`

処理の流れは **正規化 → 行の分解 → 式の構文解析 → ジェネレータで逐次実行**。

- **正規化**: 全角英数字・`＝（）［］”，：` を半角に。行頭の `(01)` を無視。`#` 以降はコメント。
- **深さ（インデント）の決め方**: 罫線 `│` `└` が1つでもあれば**その本数**が深さ。
  1つも無ければ**行頭スペース幅の順位**（2スペースでも4スペースでも動く）。
- **文の判別**は行単位の正規表現（`もし〜ならば:`、`〜を〜から〜まで〜ずつ増やしながら繰り返す:`、
  `関数定義 名前(引数...):`、`戻り値(式)` など）。
  式だけを再帰下降パーサにかけている。日本語キーワードを式パーサに食わせない構造。
- **実行は emit 方式**。1文ごとに次の形のイベントを steps 配列へ push する。これがアニメーションの素材。
  （以前はジェネレータだったが、**関数の中の処理も1ステップずつ記録する**ために emit 方式へ変更した。
  式の評価中に呼ばれたユーザー定義関数の内部ステップが、呼び出し元の代入ステップより前に正しい順で入る）
- **ユーザー定義関数**（2026-08-17追加。書き方は教材と同じ一例。公式仕様はまだ無い）:
  `関数定義 面積(teihen, takasa):` で登録し、`戻り値(keisan)` で値を返す。呼び出しは通常の式 `面積(6, 5)`。
  実行中は**ローカルスコープ**（引数＋関数内で代入した変数）に読み書きし、外の変数は読み取りのみ可。
  スナップショットにはグローバル＋実行中のローカルが混ざって入る（引数の値が見えるのが教育上の狙い）。
  再帰は深さ30まで。kind は `funcdef`（定義） / `call`（呼び出し） / `return`（戻り値）が増えた。

```js
{
  line,             // 何行目か（ハイライト用）
  kind,             // assign / cond / loop / loopiter / loopend / output / expr
                    //   / funcdef / call / return（関数）
  desc,             // 「min_tensuu = 1000 > 50 を計算して、min_tensuu は 50 になりました」
  vars,             // その時点の全変数のスナップショット（配列はコピー）
  output,           // その時点までの表示内容
  // ▼ アニメーション演出用の構造化データ（種別により付く）
  target,           // assign: 代入先 { name, index }（index は表示上の添字。スカラーは null）
  value,            // assign: 代入した値
  reads,            // assign/cond/output: 読んだ場所 [{ name, index }]（配列全体の読みは含めない）
  result,           // cond / while系: 条件の真偽
  loopVar,          // for系: { name, value } 実行中のループ変数
  text              // output: 表示した文字列
}
```

`desc` は `trace()` が「式に値を当てはめた文字列」を作って組み立てている。
ここが**生徒の理解を助ける中心**なので、文言を変えるときは丁寧に。

- **無限ループ対策**: 4000ステップで打ち切ってエラーにする。
- **エラーは日本語で具体的に**（例: 「添字が範囲外です（Seiseki の添字は 0〜4。5 が指定されました）」）。
  誤答で実行するとエラーが出るが、それも学習材料なので握りつぶさない。

### 6.4 生徒画面の操作モデル（app.js）

スマホでの操作は**3通り**を同時に成立させている。ここは実機フィードバックで何度も直した箇所なので、
触るときは §8 の経緯を必ず読むこと。

1. **タップ** → その選択肢が「選択中」になり、入る先の空欄がオレンジに点滅 → 空欄をタップで入る
2. **ドラッグ** → 選択肢が全部見えている（スクロール不要な）ときは**触ってすぐ動く**。
   はみ出してスクロールが必要なときだけ、上下スワイプはスクロールに譲り、**長押し0.2秒**でドラッグ開始
3. **空欄をタップ**（選択中の選択肢が無いとき）→ 中身を消す

判定は `syncTrayScroll()` が `chipsEl.scrollHeight > clientHeight` を見て
`.chips.scrollable` クラスと `trayScrolls` フラグを切り替えている。
CSSの `touch-action` もこのクラスで `none` ⇄ `pan-y` を切り替える。

**アニメーションパネル**は、スマホでは `body.anim-open` のとき画面下から
せり出す（`position: fixed`）。上半分にコード、下半分に変数の値が同時に見えるようにするため。
デスクトップでは右カラムに並び、`position: sticky` でスクロールに追従する。

**アニメーションの演出**（2026-08-17に作り直し。文章を読まなくても「パッと見」でわかるように）:

- **行内バッジ** `.lbadge`: 実行中の行の右端に結果を直接出す。
  代入は `total ← 50`（オレンジ）、条件は `○ 真`（緑）/`× 偽`（グレー）、
  ループは `i = 2`（青）、表示は `表示 ▶`。視線がコードから動かなくても結果がわかる
- **飛ぶ値トークン** `.fly`: 代入・表示のステップで、値が実行行から
  変数ボックス・配列セル・出力欄へ飛ぶ（Web Animations API。`prefers-reduced-motion` では出さない）
- **読み書きの色分け**: そのステップで読んだ変数・セルは青（`.src`）、
  変わった場所はオレンジのフラッシュ（`.hit`）。凡例を「変数と配列のようす」見出しに表示
- **配列カーソル**: 実行中のループ変数の位置に `▲ i` のラベルをセルの下に出す
  （`step.loopVar` を優先。無ければ i,j,k,m,n の類推）
- **変化チップ**: ナレーション欄に `total: 0 → 50` を大きく出す。条件は `○ 成り立つ（真）` の判定チップ

- これらの素材は dncl.js のステップイベント（§6.3 の target / reads / result / loopVar / text）から作る。
  ステップ連打時の残像対策として、renderVars は前回の requestAnimationFrame 予約を取り消してから光らせる

## 8. 過去のフィードバックと、その結果いまこうなっている（重要）

同じ失敗を繰り返さないための記録。

1. **「選択肢が画面外にいってスクロールもできない」**
   原因は `.chip` に `touch-action: none` を当てていたこと。指のスワイプが全部ドラッグ判定に
   吸われていた。→ スクロールが要るときだけ `pan-y` にする方式へ。さらに**トレイの実高さを
   実測して CSS変数 `--trayh` に入れ、本文の下余白に反映**するようにした（隠れなくなった）。

2. **「長押しドラッグだと文章を選択している感じになる」**
   iOSの長押しでテキスト選択の虫めがね・コピーメニューが出ていた。
   → `-webkit-touch-callout: none` と `-webkit-user-select: none`（**`-webkit-`付きが必須**）、
   `selectstart` / `contextmenu` の抑止を追加。

3. **「ちょっと触ってドラッグしたら動くようにしてほしい」**
   → 選択肢がスクロール不要なときは長押しなしで即ドラッグ（§6.4）。
   あわせて、空欄の外で指を離しても中身を消さないようにした（スクロールのつもりで消えるのを防ぐ）。

4. **「アニメーションが速い」** → 既定を1ステップ **1.7秒**に。スライダーで0.5〜3.2秒。

5. **「重複して選べるとき、選んだ選択肢を灰色にしなくていい」**
   → 使用済み表示を廃止。共通テストも「同じものを繰り返し選んでよい」形式。

6. **「URLにユーザー名が入るのが気になる」** → GitHub Pages をやめて Vercel へ移行。

### 教材づくりで守っていること

- **配列の添字を「必ず0から」と教えない**。公式例示は0始まりだが**令和7年度本試験は1始まり**。
  問題文の指示が絶対、と教える（アプリも `indexBase` で切り替えられるようにしてある）。
- 問題データの値は「その問題が意味を持つ」ように選ぶ。例えば `Seiseki = [50, 30, 60, 45, 85]` の
  30点と60点は、(4)「60点だけ据え置き」と(5)「3人に達したら打ち切り」を成立させるために入れている。
  全員35点以上だと(5)が練習にならない。
- 解説文は AIっぽい比喩（「刺さる」「強烈な」等）を使わず、平易に書く。
- **教材PDFの誤植に注意**: 講座⑨の目標心拍数の実行結果は教材では「85から136」だが、
  定義どおり計算すると (220−30)×0.5〜0.8 ＝ **95から152** になる（85/136は年齢50歳の値）。
  アプリは実際に実行して確かめられるため、正しい 95〜152 を採用した。教材側の修正を推奨。
  同じく講座③のりんご練習は、定価200円・実行結果20円と整合する `ringo = 200` を採用
  （教材のコード欄は 110 に見えるが、それだと答えが合わない）。

## 10. アクセスが増えたときの話

**完全な静的サイトで、採点もプログラムの実行もすべて生徒の端末のブラウザ内で完結する。**
サーバー側の処理・DB・API呼び出しは1つも無い。Vercelは最初にファイルを配るだけ。

| | 転送量 | リクエスト数 |
|---|---|---|
| 初回アクセス | 約25KB（br圧縮後） | 6 |
| 2回目以降 | 約1KB | 1（JS/CSSは1年キャッシュ） |

Vercel Hobby（無料）枠は 100GB/月・100万リクエスト/月。上の数字だと
**初回アクセス換算で月16万回**まで耐える。塾の規模では技術的にまず頭打ちにならない。
同時アクセスの上限も実質無い（CDN配信で、サーバー関数を1つも使っていないため）。

**ただし規約面**。Vercel の Hobby プランは**非商用のみ**。塾の生徒に配って使う以上は
Pro（**$20/ユーザー/月**、$20分の利用クレジット込み、商用可）が本来。
`bushido2` チームには英作文添削メーカーも同居しているので、そちらの契約状況とあわせて判断する。
無料のまま使いたい場合は、GitHub Pages（商用可・無料）に戻す選択肢もある。
